Session 1 Part C: Problem-Solving Techniques

Proven strategies for decomposing complex computational tasks.

Visual Representation

Draw state diagrams, tables, and flowcharts. Externalizing mental models reduces cognitive load and illuminates hidden edge cases.

Simpler Analogous Task

Scale down the problem parameters first (e.g. solve for an array of 3 items before scaling to 100,000 records).

Pattern Identification

Search for mathematical, structural, or temporal repetitions to convert manual steps into iterative loops or functions.

Systematic Elimination

Eliminate logically impossible paths first. Narrowing down the solution space increases the precision of targeted guesses.

Session 2 Part B: The 3 Fundamental Programming Constructs

The foundational building blocks of all imperative software algorithms.

1. Sequence

Instructions execute strictly line-by-line in sequential order from top to bottom without skipping or jumping.

2. Selection

Branching logic where execution paths diverge dynamically based on evaluating condition expressions (IF / ELSE).

3. Iteration

Repeating an instruction block until a termination condition evaluates to true (FOR, WHILE loops).

Session 2 Part D: Gaddis Pseudocode Conventions

Standardized pseudocode rules and structured program encapsulation.

Encapsulation Template

PROGRAM VendingMachine
1. OUTPUT "Process payment";
2. OUTPUT "Dispense item";
3. OUTPUT "Return change";
END

Core Pseudocode Syntax Rules

  • • Keywords are strictly UPPERCASE (DECLARE, SET, INPUT, OUTPUT).
  • • Program blocks are bounded by PROGRAM <Name> and END.
  • • Executable statements end with explicit semicolons (;).
  • • Statements inside blocks are explicitly numbered sequentially.

Session 3 Part D: Complete Algorithm Implementation

Keyboard input, mathematical operations, screen output, and File I/O handling.

Complete Gaddis Program Code 

PROGRAM SheepAndChickens
    DECLARE Integer sheep, chickens, legs, animals;
    DECLARE String result;

    // Manual Keyboard Input
    OUTPUT "Enter total number of legs:";
    INPUT legs;
    OUTPUT "Enter total number of animals:";
    INPUT animals;

    // Mathematical Calculations
    SET sheep = (legs - animals * 2) / 2;
    SET chickens = animals - sheep;
    SET result = "Sheep=" & sheep & " Chickens=" & chickens;

    // Screen Output & File I/O Handling
    OUTPUT result;
    OPEN "results.txt" mode write;
    WRITE result;
    CLOSE;
END

Session 4 Part B: Single & Dual Alternative Selection

Controlling execution paths through conditional IF blocks.

Single Alternative (IF)

Executes statement block only when the condition evaluates to true; otherwise skips completely.

IF sugars > 0 THEN
    OUTPUT "Add " & sugars & " sugars to tea";
END IF;

Dual Alternative (IF/ELSE)

Executes True branch if condition evaluates to true, otherwise executes False alternative branch.

IF parcelWeight > 5 THEN
    OUTPUT "Dispatch Van";
ELSE
    OUTPUT "Dispatch Motorbike";
END IF;

Session 4 Part C: Multi-Way Branching & SELECT/CASE

Evaluating complex conditional decision structures and single-variable value matches.

Chain Selection (IF/ELSE/IF)

Chaining conditional tests sequentially across multiple thresholds.

IF mark >= 70 THEN

        SET grade = "B";

Clean multi-way matching against a single variable or expression value.

SELECT errorCode

        SET errMsg = "Unknown Error";
END SELECT

Session 5 Part A: Loop Mechanisms (Pre-Test vs. Post-Test)

Iteration constructs repeat statement blocks until evaluated condition thresholds change.

Pre-Test Loops (WHILE / FOR)

Condition is tested BEFORE executing the body. If the condition evaluates to false at start, the loop body runs 0 times.

WHILE condition
// Executes only if condition is true
END WHILE

Post-Test Loops (DO...WHILE)

Statements run once BEFORE checking condition at the end. Guaranteed to run at least once (1+) regardless of initial condition state.

DO
// Runs at least once
WHILE condition;

Session 5 Part B: Count-Controlled Loops

Utilized when iteration count is known in advance via counter initialization and step tracking.

1. WHILE Count-Controlled

Explicit counter declaration, initialisation, condition check, and manual incrementing within the loop body.

DECLARE Integer counter, limit;
SET limit = 10;
SET counter = 0;
WHILE counter < limit
    OUTPUT counter;
    SET counter = counter + 1;
END WHILE;

2. FOR Compact Loop

Initialises counter, end limit, and step direction inside the loop header for cleaner code.

DECLARE Integer counter, CAPACITY;
SET CAPACITY = 8;
FOR counter = 1 TO CAPACITY STEP 1
    OUTPUT "FETCH parcel";
    OUTPUT "Parcel loaded count = " & counter;
END FOR;
OUTPUT "Dispatch Van";

Session 5 Part C: Condition-Controlled & File EOF Loops

Iterates while external logical state conditions remain True (e.g. payload thresholds or file stream limits).

Parcel Payload Loader Algorithm (WHILE NOT EOF())

Reads parcel weights from file stream until End-Of-File flag (EOF()) or payload limit condition occurs.

PROGRAM ParcelLoader
    DECLARE Real payload, parcelWeight, CAPACITY;
    DECLARE Integer parcelCount;

    SET parcelCount = 0;
    SET CAPACITY = 500.0;
    SET payload = 0.0;
    OPEN "parcels.txt" mode READ;

    WHILE NOT EOF()
        READ parcelWeight;
        IF payload + parcelWeight <= CAPACITY THEN
            SET parcelCount = parcelCount + 1;
            OUTPUT "Parcel weighing " & parcelWeight & "kg loaded";
            SET payload = payload + parcelWeight;
        ELSE
            OUTPUT parcelWeight & "kg parcel too heavy for van";
        END IF;
    END WHILE;

    OUTPUT "Dispatch Van carrying " & parcelCount & " parcels.";
    CLOSE;
END

Session 5 Part D: Post-Test DO...WHILE Loop Example

Ensures prompt execution executes once before validating user access credentials.

PIN Verification Turnstile System

Prompts user for PIN entry at least once, repeating prompt until correct PIN opens turnstile.

DECLARE String code, storedCode;
DECLARE Boolean turnstileOpen;
SET storedCode = "1234";
SET turnstileOpen = false;

DO
    OUTPUT "Enter 4 digit PIN code:";
    INPUT code;
    IF code == storedCode THEN
        SET turnstileOpen = true;
    END IF;
WHILE turnstileOpen == false;

OUTPUT "PIN correct - Turnstile opened";

Summary of Loop Selection Rules

Use FOR Loop:

When exact iteration count is known before loop execution.

Use WHILE Loop:

When iteration depends on variable state & zero executions are valid.

Use DO...WHILE Loop:

When input validation requires at least one initial execution.
